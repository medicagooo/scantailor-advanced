# CLI 3 键盘与鼠标菜单

双击 `scantailor-cli.exe`，或在 Windows Terminal / 控制台运行 `scantailor-cli.exe menu`。
便携包自带 Python；源码构建可传 `menu --python <python.exe>`。重定向输入输出时无参数不会进入菜单，原有自动化命令继续使用 JSONL。

方向键、Tab、翻页键选择，Enter 或单击执行，Esc 返回。文件选择器支持驱动器、目录、路径输入、多文件勾选与新建输出子目录；多选顺序就是处理顺序。菜单忽略没有绑定的快捷键和按住确认键的重复事件。文本框限定当前字段输入，数字字段拒绝字母。Windows 快捷键仍由操作系统或终端处理。

表单中的值是草稿，应用才写入父表单；最外层应用才成为当前配置。Esc / 放弃恢复进入表单前的值。未设置的字段沿用项目值；删除字段移除覆盖，空区域数组表示清除区域。嵌套数组可编辑、添加、删除、排序，不需要编写 JSON。字段类型、枚举和范围直接来自原生 `config schema`；跨字段和项目语义由原生 CLI 再验证，失败会显示日志。

输入改变后，旧配置覆盖、选页范围和预览标记重置，避免源 ID 与坐标误用。源图级设置仅允许 images/image_ids 规则；逻辑页规则用于拆页后的页面。项目菜单能从实际页面列表创建规则，无需抄写 ID。对内容矩形自动附加当前项目的几何 basis；先分析到 deskew 并载入其项目，再编辑手动框。高级表单也提供全部坐标字段，单位像素；边距和冻结尺寸单位毫米。详见 CLI.md 的几何空间定义。

菜单包括全局和逐页参数、六阶段分析和预览、插入/移除/恢复半页/排序/重新关联、配置导入导出、坐标转换与同包 GUI 编辑。项目操作先 dry-run，通过后另存到任务目录，成功后才载入新项目。GUI 编辑使用私有项目副本，关闭 GUI 后才重新载入。

PDF 精确选择写入路径清单，只处理勾选的 PDF。同名不同目录的 PDF 使用独立输出子目录。PDF 分析/预览会渲染源页并运行对应原生阶段，不必先生成最终 PDF；从任务结果打开生成的 .scan，即可逐页编辑。生成项目后的图像流程输出 TIFF；PDF 的原始尺寸保留与重新组装仍由 PDF 入口完成。

运行期间输入、配置和项目锁定；可以查看进度、请求取消。取消发送 Ctrl+Break 到工作进程组并等待退出，PDF 包装层不会超时强杀正在写检查点的原生进程。退出菜单前必须结束任务。退出码 1 明确显示“复核 / 部分失败”，不能当成全部成功。

每次运行在 `%LOCALAPPDATA%/ScanTailorCLI/menu/<任务ID>` 写入输入清单、配置快照、命令、日志与状态。历史恢复使用该任务的原快照，当前表单的改动不会混入恢复任务。原生指纹和 PDF 指纹负责检查源、配置、程序与输出哈希。中间文件保留以供复核与恢复；不会自动清除旧任务。`--state-dir` 可指定菜单记录目录。

代码关系：`src/cli/MenuLauncher.cpp` 转交交互控制台给 `scripts/menu.py`；`scantailor_menu/console.py` 统一输入记录和命中区域，`ui.py` 提供表单与项目命令适配，`model.py` 固定任务快照并收集子进程日志。PDF 工作层是 `process_pdf_folder.py`，处理算法仍由共享的原生六阶段执行。

验证入口：`python tests/menu_integration.py --cli build-native/scantailor-cli.exe -v`。控制台测试创建隐藏 Windows 控制台，使用真实 WriteConsoleInputW/ReadConsoleInputW 验证键盘、鼠标、文本、模式恢复与原生菜单入口；它不等于人工在 Windows Terminal 中点击验证。
